# 销售数据分析项目

## 项目简介

本项目**数据集由 Python 脚本模拟生成**，基于订单、客户、产品、退货四份 CSV 业务数据集，利用RFM 模型完成数据分层，使用 **SQL + Power BI** 完成销售数据分析。完成数据导入、模型搭建、指标计算、可视化报表输出，输出总销售额、分品类销售额、订单数量、退货订单数、退货原因分布等业务指标，完成 SQL 与 Power BI 数据对账，保证两边计算口径统一。

## 指标业务口径

1. 行销售额 = 订单数量 × 产品单价
2. 总销售额：全部订单行销售额求和；统计销售额时不关联退货表
3. 总订单数：去重订单 ID 计数
4. 退货订单数：发生过退货的**去重订单 ID 计数（共 93 个）**，区别于退货记录条数（共 96 条）
5. 退货率 = 退货订单数 / 总订单数
6. 退货原因分布：按**去重退货订单**统计；同一订单多条退货记录若原因不同，订单会被计入多个原因分类，分项合计可能大于总退货订单数。

## 完整项目流程

### 步骤 1：数据生成与理解

1. 使用 Python 脚本模拟业务，生成`customer.csv`、`order.csv`、`product.csv`、`return.csv`四份模拟业务数据；
2. 梳理每张表字段、主键、表之间关联关系；
3. 确认关联键：`customer_id`、`order_id`、`product_id`；
4. 识别业务特点：order 为事实明细表；customer、product 为维度表；return 为退货事件表，存在**一个订单多条退货记录**的情况。

### 步骤 2：SQL 数据处理与指标计算

1. 将 csv 数据导入数据库，完成建表。
2. 分开处理销售指标与退货指标：
   - 子查询 1：关联订单表与产品表，计算各品类销售额、总订单数，不引入退货表；
   - 子查询 2：关联退货、订单、产品表，统计各品类退货订单数量；
3. 执行 SQL，得到各品类销售及退货结果，记录结果作为基准数据。

> 
> SQL 完整代码

```
SELECT product.category,SUM(`order`.quantity*product.unit_price) AS 销售额,
       COUNT(DISTINCT `order`.order_id) AS 订单数
FROM `order`
LEFT JOIN product ON product.product_id = `order`.product_id
GROUP BY product.category
ORDER BY 销售额 DESC;

SELECT product.category,COUNT(DISTINCT `return`.order_id) AS 退回订单数,
      ROUND(COUNT(DISTINCT `return`.order_id)/COUNT(DISTINCT `order`.order_id),3) AS 退货率
FROM `order`
LEFT JOIN `return` ON `return`.order_id = `order`.order_id
LEFT JOIN product ON product.product_id = `order`.product_id
GROUP BY product.category;
```

### 步骤 3：Power BI 数据导入与数据模型构建

1. 在 Power BI 中导入 4 个 CSV 文件：customer、order、product、return；
2. 建立表之间关系，全部使用**单向筛选**，不开启双向交叉筛选：
   - product [product_id] 一对多 → order [product_id]
   - customer [customer_id] 一对多 → order [customer_id]
   - return [order_id] 多对一 → order [order_id]
3. 确认所有关系处于激活状态。

### 步骤 4：编写 DAX 度量值

```
总销售额 = 
SUMX(
    'order',
    'order'[quantity] * RELATED('product'[unit_price])
)

总订单数 = DISTINCTCOUNT('order'[order_id])

退货订单数 = CALCULATE(DISTINCTCOUNT('return'[order_id]),TREATAS(VALUES('order'[order_id]),'return'[order_id]))

退货率 = DIVIDE([退货订单数],[总订单数],0)

客单价 = DIVIDE([总销售额],[总订单数],2)
```

### 步骤 5：报表可视化制作（共 3 个报表页面：总览页、产品分析页、客户分析页）

#### 页面 1：总览页（全局核心指标概览）

- 卡片：放置产品品类字段，搭配【总销售额】【总订单数】【客单价】【退货率】度量，输出分品类业务指标；
- 折现图：销售额趋势图(年月)；
- 饼图：各区域销售情况。

#### 页面 2：产品分析页（品类与产品维度分析）

- 表格：产品销量 TOP10；
- 饼图：品类销售额、退货原因分布；
- 柱状图：各品类退货情况。

#### 页面 3：客户分析页（RFM分析、地区、行业客户维度分析）

- 饼图：按行业维度展示客户分布，RFM展示客户分层占比；
- 柱状图：不同分层客户销售额占比；
- 切片器：地区、行业，实现客户维度交互式筛选。

### 步骤 6：跨工具数据对账校验

1. 将 Power BI 输出的总销售额、各品类销售额、总订单数、退货订单数，和 SQL 执行结果逐项比对；
2. 重点校验：卡片图`退货订单数`输出结果必须为 93，区分退货记录数 96；
3. 确认全部指标数值保持一致，统一 SQL 与 PowerBI 口径。

### 步骤 7：输出交付

输出 PowerBI 报表 pbix 文件，留存 SQL 脚本，整理指标结果，完成项目交付。

## 业务洞察

1. **销售结构洞察**

- B 类辅材是第一大收入来源，销售额占比 35.46%，同时订单总量最高，是核心营收品类。A 类主材、C 类配件销售额规模接近，整体形成三足鼎立的销售格局。
- B 类辅材退货率 9.11%，明显高于 A 类主材 6.86%、C 类配件 7.00%，售后风险更高，需要重点关注。A 类主材与 C 类配件业务表现更加稳定。

2. **退货业务洞察**

- 整体订单退货率 7.75%，退货分为客户取消、质量问题、发货错误三类原因。饼图按照**去重退货订单**统计；由于存在一个订单多条不同原因的退货记录，饼图分项数值相加会大于总退货订单 93 个。
- 部分订单产生多条退货记录，会增加售后团队的人力处理成本。

3. **客户拓展潜在方向**

- 通过客户分析页可以查看不同地区、不同行业的销售表现，可进一步挖掘高销售额、低退货率的行业与区域，作为业务重点拓展方向。

## 落地建议

1. **产品与供应链优化**

- 针对 B 类辅材高退货率，结合退货原因分布做根因定位：质量问题则加强供应链品控；发货错误则优化仓库拣货出库复核流程；客户取消占比高则优化售前产品介绍，减少冲动下单。
- A 类主材、C 类配件退货表现稳定，可以适当加大营销资源投入，进一步提升销售规模。

2. **售后流程优化**

- 系统增加重复退货订单标记，对同一订单多次发起退货进行自动预警，降低售后重复处理成本。

3. **数据看板体系建设**

- 将本项目 SQL、DAX 度量逻辑固化，对接定时更新业务数据源，实现销售、退货指标自动化看板，替代手工统计。
- 基于现有三页报表，可继续增加时间维度分析，跟踪销售额、退货率随时间的波动，识别业务淡旺季。
- 拓展客户分层分析，挖掘高价值客户群体，支撑精细化客户运营。

4. **报表业务使用建议**

> 
> 三页报表分工：
> 
> 
> - 总览页：给管理层看，快速掌握整体经营 KPI 与退货概况；
> - 产品分析页：产品、运营人员使用，聚焦品类销售与退货表现；
> - 客户分析页：销售业务人员使用，用于地区、行业客户的业务复盘。
> PowerBI 看板可共享给销售、运营、售后团队，实现数据驱动业务决策。
